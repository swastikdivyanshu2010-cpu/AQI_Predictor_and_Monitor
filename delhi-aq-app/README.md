# Delhi PM2.5 Next-Day Forecast // School Outdoor Activity Decision Tool

> **Hackathon Prototype** • Replay of held-out test days, not a live forecast.  
> Prioritising operational clarity, child safety, and honest evaluation over artificial polish.

An end-to-end machine learning pipeline and bespoke data journalism web dashboard (inspired by *Our World in Data*, *Bloomberg Graphics*, and Swiss Grid Typography) designed for a Delhi school coordinator deciding whether morning outdoor assemblies, physical education (PE), and sports practice can go ahead tomorrow.

---

## 📌 Executive Summary

Predicting PM2.5 in Delhi is notoriously difficult due to extreme winter inversions, stubble burning plumes, and episodic festival combustion (Diwali firecrackers). While standard regression models often report single-number test errors, **school coordinators face an asymmetric loss function**:
- **A false alarm (unnecessary cancellation)** causes minor administrative inconvenience.
- **A missed warning (false negative)** exposes thousands of children, including asthmatic students, to hazardous particulate matter exceeding 250–350 µg/m³.

This prototype compares an 18-feature **HistGradientBoostingRegressor** against a naive **Persistence Baseline ("Tomorrow = Today")** across a 120-day held-out test set and multi-season walk-forward backtests. The pipeline achieves **95.8% decision accuracy** (point forecast rule) with 93.5% precision and 90.6% recall at the Indian National Ambient Air Quality Standard (NAAQS) limit of 60 µg/m³. It calibrates **90% prediction intervals** (`q90 = 33.0 µg/m³`, yielding 85.8% empirical held-out coverage) alongside secondary 80% intervals (`q80 = 20.7 µg/m³`, 80.8% coverage), and supports **three distinct operational decision policies** (`pt`, `ct`, `pr`), proving how an uncertainty-aware conservative threshold policy achieves **100% child-safety recall (0 missed hazardous days)**.

export OPENAQ_API_KEY="your-openaq-api-key"
python forecast_live.py

## 🛰️ Live Forecast System Architecture

The application features a dual-mode engine:
1. **LIVE FORECAST (unverified)**: Fetches the latest next-day PM2.5 prediction generated by a scheduled GitHub Actions workflow.
2. **HELD-OUT REPLAY (evaluated)**: Inspects the 120-day test set containing ground-truth measurements, backtest metrics, and policy threshold tables.

### 1. GitHub Actions Scheduled Refresh (`.github/workflows/refresh.yml`)
- Runs **every 6 hours** (`0 */6 * * *`) and on manual `workflow_dispatch`.
- Steps executed in CI:
  1. Clones repository with Git credentials.
  2. Sets up Python 3.11 with cached pip dependencies from `requirements.txt`.
  3. Executes `python forecast_live.py` using `OPENAQ_API_KEY` stored in GitHub Actions secrets.
  4. If `latest.json` has changed, commits and pushes `latest.json` directly back to `main`.
- **Configuring GitHub Secret**:
  1. Navigate to your GitHub repository: `Settings` → `Secrets and variables` → `Actions`.
  2. Click **New repository secret**.
  3. Name: `OPENAQ_API_KEY`.
  4. Value: *Your OpenAQ API Key* (from [OpenAQ Account Console](https://openaq.org/)).

### 2. Data Sourcing & API Latency Handling
- **Station Identification**:
  - Saved in `data/station.json` (`location_id: 8118`, `sensor_id: 23534`, `"New Delhi"`).
  - Matches the exact monitoring sensor used for historical evaluation.
- **Partial Day Exclusion**:
  - In air quality monitoring, calculating 24h daily mean PM2.5 from an incomplete day introduces severe daytime bias.
  - `forecast_live.py` strictly computes timestamps in **Asia/Kolkata (IST)**, excludes the ongoing incomplete day, and bases the forecast on the latest fully completed 24-hour observation cycle (`issued_on`), forecasting for `forecast_for = issued_on + 1 day`.
- **Open-Meteo Forecast vs. Archive Endpoint**:
  - The historical training archive uses Open-Meteo's reanalysis archive, which undergoes quality checks and has a 2–5 day reporting latency.
  - The live inference pipeline uses the **Open-Meteo Forecast API** (`api.open-meteo.com/v1/forecast?past_days=14`), combining recent surface observations with numerical weather prediction (NWP) forecasts for temperature, wind speed, wind direction, and precipitation tomorrow.
- **Station Outage & Gap Fallback**:
  - If the OpenAQ station experiences network downtime or missing readings (>3 missing lag days), `forecast_live.py` writes a graceful `{"status": "unavailable", "message": "..."}` payload to `latest.json`.
  - The frontend detects this state and automatically falls back to replay mode with an informative notice.

### 3. Shared Features & Train-Serve Parity (`features.py`)
To prevent train-serve mismatch, feature engineering is centralized in `features.py` and imported by both `export_final_results.py` and `forecast_live.py`. The model evaluates exactly 18 features in fixed order:
1. `pm25_today` (Persistence anchor)
2. `pm25_lag1`, `pm25_lag2`, `pm25_lag3`, `pm25_lag6` (Autoregressive lags)
3. `pm25_mean3`, `pm25_mean7` (Rolling momentum windows)
4. `temp`, `wind_speed`, `wind_dir_sin`, `wind_dir_cos`, `rain` (Meteorological drivers)
5. `season_sin`, `season_cos` (Annual cyclical solar calendar)
6. `humidity` (Relative humidity at 2m, proxy for particulate hygroscopic growth)
7. `temp_range` (Diurnal temperature range `temperature_2m_max - temperature_2m_min`, proxy for nocturnal boundary layer stability / thermal inversions)
8. `wind_calm` (Stagnation index: binary flag `1.0` if `wind_speed_10m_max < 1.5` m/s, else `0.0`)
9. `diwali_window` (Episodic combustion calendar flag: `1.0` if within Diwali festival window, else `0.0`)

### 4. Scientific Honesty & Labeling
- Live forecasts have **no ground truth yet** (`actual: null`).
- The dashboard strictly suppresses historical evaluation metrics (MAE, prediction interval coverage, recall, threshold tables) in Live Mode, labeling the prediction unambiguously as **`LIVE FORECAST (unverified)`** to prevent coordinators from mistaking past backtest accuracy for real-time certainty.

* **Right Column (62%) — Interactive Chronological Trajectory Chart**:
  * High-density Recharts trajectory curve showing actual station readings (OpenAQ), model predictions (Signal Blue `#1D4ED8`), persistence baseline, and shaded 90% confidence interval band (`lower_90` to `upper_90`, with secondary 80% interval).
  * Dashed threshold line at 60 µg/m³ in Signal Vermilion.
  * Vertical reference marker for Diwali dates.
  * Custom crosshair tooltip with click-to-select interaction.

### 2. Bottom Ticker Strip
A continuous 4-column ledger comparing:
1. **Model Projection** (`306.8 µg/m³`)
2. **90% Confidence Interval** (`273.8 – 339.7 µg/m³`)
3. **Persistence Benchmark ("Tomorrow = Today")** (`317.0 µg/m³`)
4. **Held-Out Test Error** (`|58.8| µg/m³`)

### 3. Honest Benchmarking & Performance Ledger (Table 1.0)
* **Decision Accuracy (@ 60 µg/m³)**: Achieves **95.8% decision accuracy** (`decision_accuracy_pt`), **93.5% precision** (`precision_pt`), and **90.6% recall** (`recall_pt`) under the point forecast rule (`pt`), alongside **95.0% decision accuracy** (`decision_accuracy_pr`) under the risk-calibrated rule.
* **90% Prediction Interval Coverage**: **85.8% empirical range coverage** on the calibrated 90% prediction interval (`q90 = 32.96 µg/m³`), alongside **80.8% coverage** on the secondary 80% interval (`q80 = 20.67 µg/m³`), confirming reliable probabilistic error bounds.
* **Test Window MAE vs. Baseline**: On the 120-day held-out summer/monsoon test window (±15.41 µg/m³ model vs ±13.75 µg/m³ baseline), persistence matches the model due to persistent calm summer weather regimes.
* **Full Multi-Season Backtest MAE**: Over full expanding seasonal backtests including autumn crop-burning and winter thermal inversions, the model outperforms baseline by **16.75 vs 17.70 µg/m³**.
* **Child Safety Recall**: **100% recall (0 missed hazardous days)** at the 60 µg/m³ regulatory threshold under the Conservative 90% Rule (`alert_90`).

### 4. Decision Policy Matrix (Table 2.0)
Evaluates three operational rules across PM2.5 thresholds (35, 60, 90, 120, 250 µg/m³):
- **Point Forecast Rule (`pt`)**: Alert if `model > threshold`. Delivers **95.8% decision accuracy** and **93.5% precision** at 60 µg/m³, minimizing false alarms for administrative efficiency.
- **Conservative 90% Rule (`ct` / `alert_90`)**: Alert if `upper_90 > threshold`. **Zero missed bad air days (100% recall)** at 60 µg/m³—the optimal choice for schools prioritizing child safety.
- **Risk-Calibrated Rule (`pr`)**: Compromise policy alerting if `model + 0.5 * (upper_90 - model) > threshold`, achieving **95.0% decision accuracy**.

### 5. Documented Physical Failure Modes ("Where It Fails")
Editable field notes highlighting real atmospheric failure modes:
1. **Diwali Combustion Spike Lag**: Weather features do not capture unmeasured firecracker detonations; calendar features soften the blow but point forecasts still underestimate peak burst.
2. **Nocturnal Thermal Inversions**: Calm wind speeds (< 1.5 m/s) trap ground emissions overnight, creating morning spikes before boundary-layer mixing occurs.
3. **Precipitation Recovery Rebound**: Tropospheric washouts clear particulate rapidly, but road dust and stubble smoke re-accumulate faster than tree-based models project.

### 6. Coordinator Advisory Dispatch Generator
* One-click generation of a 2-sentence operational notice ready for transmission to parents and faculty via WhatsApp broadcast or morning announcements.
* Powered by Google Gemini Flash (when API key is provided, strictly constrained to selected day's numbers with zero hallucinations allowed) or an instant **deterministic offline template**.
